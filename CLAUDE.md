## ANTI-PATTERNS

- **Prefer NOT to edit `blog/themes/next/` directly** — override via `blog/source/_data/next.yml`. Small config-only changes (e.g., menu entries) in `themes/next/_config.yml` are OK when no `_data/` dir exists yet.
- **Do NOT remove the image symlink** at `astro/public/image` — blog posts reference `/image/...`
- **Do NOT commit `dist/`, `blog/public/`, `blog/.deploy_git/`** — generated outputs
- **Do NOT use `npm run` in blog/** — bin symlinks may be broken; use `node node_modules/hexo/bin/hexo` instead
- **Do NOT run `hexo deploy`** — CI handles deployment now
- **Do NOT resurrect `resume/genresume.sh` / Pandoc** — resume is now native Astro (see RESUME WORKFLOW)
- **Do NOT hardcode colors in page `<style>`** — use the CSS variables defined in `Layout.astro` `:root`

## RESUME WORKFLOW

Resume is a **native Astro feature** — no Pandoc, no separate repo. Source of truth:

- `astro/src/content/resume/cn.yaml` / `en.yaml` — structured bilingual data (edit prose here)
- `astro/src/content.config.ts` — Zod schema validating the YAML
- `astro/src/components/Resume.astro` + `layouts/ResumeLayout.astro` — rendering (light, print-ready)
- Served at `/resume` (中文) and `/resume-en` (English)

To update: edit the YAML, then rebuild. Long paragraphs are one physical line per item
(YAML plain scalars need no quotes/escaping for Chinese; avoid wrapping so no stray spaces appear).

**Regenerate downloadable PDFs** (uses system Google Chrome — no browser download):
```bash
cd astro && npm run build && npm run resume:pdf   # → public/resume_{cn,en}.pdf
```
Set `CHROME_CHANNEL` to override the Chrome channel if needed.

## INSTRUCTION-FILE CONVENTION

`CLAUDE.md` is the canonical instruction file (Claude Code auto-loads it). Each `AGENTS.md`
is a symlink → `CLAUDE.md` in the same dir, so Codex (which reads `AGENTS.md`) sees the same
content. Edit `CLAUDE.md`; never edit `AGENTS.md` directly (it's just a link).
